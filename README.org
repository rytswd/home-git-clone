** 🌄 Overview

*home-git-clone* is a [[https://github.com/nix-community/home-manager][Home Manager]] module that lets you define repositories in your Nix configuration and have them automatically cloned during ~home-manager switch~.

*Instead of running this on every machine...*

#+begin_src bash
git clone git@github.com:user/dotfiles.git ~/Coding/dotfiles
git clone git@github.com:user/project.git ~/Coding/project
#+end_src

*Just declare this once:*

#+begin_src nix
home.gitClone."Coding/dotfiles".url = "git@github.com:user/dotfiles.git";
home.gitClone."Coding/project".url = "git@github.com:user/project.git";
#+end_src

Run ~home-manager switch~ and your repositories appear. *Define once, deploy everywhere.*

** ✨ Features

- *Declarative* — Define repositories in Nix, clone automatically
- *Remote Preflight* — Every remote verified before activation mutates anything, all failures reported at once
- *Doctor App* — ~nix run github:rytswd/home-git-clone#check~ probes any machine's repositories ad hoc
- *Auto Default Branch* — Detects "main" vs "master" automatically
- *Git + Jujutsu* — Full support for both VCS systems
- *Worktree Ready* — Optional path structure for easy worktree workflows
- *Smart HTTPS* — Bypasses git config rewrites for HTTPS URLs
- *Auto-Update* — Optionally pull/fetch on every activation
- *Multi-User Safe* — Each user's credentials, isolated operations
- *GPG Agent* — Automatic SSH socket detection
- *Systemd Mode* — Optional retrying clone execution outside activation (Linux)

** 🚀 Quick Start

*** 1. Add the Module

**** Using Flakes (Recommended)

#+begin_src nix
# flake.nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    home-manager.url = "github:nix-community/home-manager";
    home-git-clone.url = "github:rytswd/home-git-clone";
  };

  outputs = { nixpkgs, home-manager, home-git-clone, ... }: {
    homeConfigurations.youruser = home-manager.lib.homeManagerConfiguration {
      pkgs = nixpkgs.legacyPackages.x86_64-linux;
      modules = [
        home-git-clone.homeManagerModules.default
        ./home.nix
      ];
    };
  };
}
#+end_src

**** Without Flakes

#+begin_src nix
# home.nix or configuration.nix
{ config, pkgs, ... }:
{
  imports = [
    (builtins.fetchGit {
      url = "https://github.com/rytswd/home-git-clone.git";
      ref = "main";
    } + "/nix")
  ];
}
#+end_src

*** 2. Configure Repositories

#+begin_src nix
# home.nix
{
  home.gitClone = {
    "Coding/dotfiles" = {
      url = "git@github.com:user/dotfiles.git";
    };
  };
}
#+end_src

*** 3. Activate

#+begin_src bash
home-manager switch
#+end_src

Your repository is now at =~/Coding/dotfiles/=.

#+html:<details>
#+html:<summary><strong>Auto-Update</strong> — Pull latest on every activation</summary>

Pull latest changes every time you run ~home-manager switch~. Retries up to 3 times with exponential backoff for transient network failures (e.g., DNS not yet available during ~nixos-rebuild switch~).

By default, a failed update is an error. Set ~updateFailMode = "warn"~ to log a warning and continue instead.

#+begin_src nix
home.gitClone = {
  "Coding/always-fresh" = {
    url = "git@github.com:user/repo.git";
    update = true;
  };

  # Non-critical repo: warn on failure instead of erroring
  "Coding/nice-to-have" = {
    url = "https://github.com/user/repo.git";
    update = true;
    updateFailMode = "warn";
  };
};
#+end_src

#+html:</details>

#+html:<details>
#+html:<summary><strong>Worktree Mode</strong> — Structure for git worktree workflows</summary>

Appends the branch name to the path, perfect for Git worktree workflows.

#+begin_src nix
home.gitClone = {
  "Coding/my-project" = {
    url = "git@github.com:user/project.git";
    rev = "main";
    useWorktree = true;
  };
};
#+end_src

#+begin_example
Result: ~/Coding/my-project/main/
#+end_example

Add more worktrees easily:

#+begin_src bash
cd ~/Coding/my-project/main
git worktree add ../develop
git worktree add ../feature-x
#+end_src

#+begin_example

#+end_example

*** Preflight and Doctor

#+html:<details>
#+html:<summary><strong>Remote Preflight</strong> — Catch unreachable repositories before anything changes</summary>

Before Home Manager writes anything, every configured remote (both ~home.gitClone~ and ~home.jjClone~) is probed with a short ~git ls-remote~ (10 second timeout per repository). All failures are aggregated into a single report — repository, URL, and a one-line cause each — and activation aborts before any mutation, so one missing SSH key no longer fails the generation midway with a raw git error.

#+begin_example
home-git-clone: remote preflight failed for 2 of 5 probed repositories:
  - Coding/dotfiles (git)
      url:   git@github.com:user/dotfiles.git
      cause: git@github.com: Permission denied (publickey).
  - Coding/notes (jj)
      url:   git@github.com:user/notes.git
      cause: timed out after 10s
Aborting before any changes were made (home.cloneVerifyRemotes = "fail").
#+end_example

The probes also run during ~home-manager switch --dry-run~, turning a dry run into a real preflight for the target machine. Repositories already on disk are skipped unless they would pull/fetch fatally (~update = true~ with ~updateFailMode = "error"~), so a fully-cloned machine still activates while offline. When a repository pins a ~rev~, the probe asks the remote for that branch specifically, so a typo'd or upstream-deleted branch is also caught before anything changes.

The behaviour is controlled by a single module-level option:

#+begin_src nix
home.cloneVerifyRemotes = "fail";  # default; abort activation on unreachable remotes
home.cloneVerifyRemotes = "warn";  # print the report but continue
home.cloneVerifyRemotes = "off";   # no preflight
#+end_src

Use ~"warn"~ for bootstrap flows where credentials arrive only after the first activation (e.g. an SSH key placed by a secrets service once the user session exists): the first switch proceeds, and the repositories appear on a later one.

#+html:</details>

#+html:<details>
#+html:<summary><strong>Repository Manifest</strong> — The configured repo set as JSON on the live system</summary>

Whenever repositories are configured, the module renders them as JSON into the generation and links it at =~/.config/home-git-clone/manifest.json= (respecting ~xdg.configHome~):

#+begin_src json
{
  "version": 1,
  "repos": [
    {
      "name": "Coding/dotfiles",
      "kind": "git",
      "url": "git@github.com:user/dotfiles.git",
      "path": "/home/user/Coding/dotfiles",
      "rev": null,
      "update": false,
      "updateFailMode": "error",
      "bypassGitConfig": false
    }
  ]
}
#+end_src

The manifest always describes the current generation, so tools (like the doctor app below) can inspect the live repository set without evaluating the Nix configuration that produced it.

#+html:</details>

#+html:<details>
#+html:<summary><strong>Doctor App</strong> — Probe any machine's repositories ad hoc</summary>

The ~check~ app reads a manifest, runs the same probes as the activation preflight, prints a table, and exits 0 when every remote is reachable (1 otherwise):

#+begin_src bash
nix run github:rytswd/home-git-clone#check                    # reads ~/.config/home-git-clone/manifest.json
nix run github:rytswd/home-git-clone#check -- manifest.json   # explicit manifest file
#+end_src

#+begin_example
REPO                    | URL                                  | STATUS
----------------------------------------------------------------------
Coding/dotfiles (git)   | git@github.com:user/dotfiles.git     | OK
Coding/notes (jj)       | git@github.com:user/notes.git        | FAIL

unreachable repositories:
  - Coding/notes (jj)
      url:   git@github.com:user/notes.git
      cause: git@github.com: Permission denied (publickey).
#+end_example

This is handy at deploy time: before switching a target host, run the doctor on it (or copy its manifest and probe from anywhere) to confirm every repository will be cloneable — no Home Manager evaluation required on the probing machine.

Note one deliberate difference from the activation preflight: the doctor probes *every* configured repository, whether or not it is already cloned locally — it answers "could this manifest be provisioned from scratch?". A fully-cloned machine that is offline can therefore activate fine while the doctor reports failures.

#+html:</details>

*** Symlinking Files

Since repositories are cloned directly to your home directory (outside the Nix store), you can symlink files or directories from them using ~config.lib.file.mkOutOfStoreSymlink~.

This is particularly useful for managing configuration files:

#+begin_src nix
{ config, ... }: {
  home.gitClone."Coding/dotfiles" = {
    url = "git@github.com:user/dotfiles.git";
  };

  # Link a directory from the cloned repo to ~/.config
  home.file.".config/nvim".source =
    config.lib.file.mkOutOfStoreSymlink "${config.home.homeDirectory}/Coding/dotfiles/nvim";
}
#+end_src

** ⚙️ Advanced Usage

#+html:<details>
#+html:<summary><strong>Override Git Config Bypass</strong> — Control HTTPS/SSH rewriting behavior</summary>

By default, HTTPS URLs bypass your git config to prevent =url.*.insteadOf= rewrites. Override this behavior:

#+begin_src nix
home.gitClone = {
  # Force bypass even for SSH
  "special/repo1" = {
    url = "git@github.com:user/repo.git";
    bypassGitConfig = true;
  };

  # Use git config even for HTTPS
  "special/repo2" = {
    url = "https://github.com/user/repo.git";
    bypassGitConfig = false;
  };
};
#+end_src

#+html:</details>

#+html:<details>
#+html:<summary><strong>Systemd Execution Mode</strong> — Retry transient clone failures outside activation</summary>

By default, clones run inline during activation, so a transient network flake mid-transfer fails the generation. On Linux you can move the clone execution into a oneshot systemd user service instead:

#+begin_src nix
home.cloneUseSystemdService = true;
#+end_src

- Activation triggers ~home-git-clone.service~ (non-blocking) and finishes immediately; the service also runs at login as a fallback when the user bus is unreachable during activation.
- The service retries on failure (~Restart=on-failure~, 30s apart, capped at 5 attempts per 10 minutes), so transient flakes recover without failing generations. Idempotency means retries skip already-cloned repositories.
- Interrupted clones are safe: repositories are cloned into a temporary sibling directory and renamed into place only on completion, so a run killed mid-clone (logout without lingering, ~SIGKILL~ after ~TimeoutStopSec~) is simply redone on the next trigger instead of leaving a torn repository behind.
- The remote preflight (~home.cloneVerifyRemotes~) still runs during activation, so genuinely unreachable remotes remain loud and early.
- Clone output moves from the activation transcript to the journal: ~journalctl --user -u home-git-clone~.

Requires systemd ≥ 244. On other platforms the option is ignored with a warning and clones run inline, so a shared configuration stays portable.

*** Key Behaviors

| Behavior        | Description                                              |
|-----------------+----------------------------------------------------------|
| *Idempotent*    | Safe to run repeatedly — existing repos left untouched   |
| *Preflight*     | Remotes verified before any mutation; dry runs probe too |
| *SSH Detection* | Auto-uses GPG agent socket at =~/.gnupg/S.gpg-agent.ssh= |
| *HTTPS Bypass*  | Prevents =url.*.insteadOf= rewrites for HTTPS URLs       |
| *Update Mode*   | Only fetches/pulls when =update = true=                  |
| *Parallel Safe* | Multiple repos clone independently                       |

** ⚠️ Known Limitations

*** No Automatic Deletion
Removing a repository from your configuration *does not* delete the directory from your disk. This is a deliberate safety feature to prevent accidental data loss. You must manually remove the directory if it is no longer needed.

*** No URL Validation on Existing Repos
If the target directory already contains a Git repository, the module *assumes it is correct*. It does not validate that the local repository's remote URL matches the one specified in your configuration. This ensures that manually modified remotes (e.g., using different push URLs) are not overwritten or flagged as errors.

*** Empty Remotes Are Rejected
A repository that was created but never pushed (no branches yet) fails both the preflight and the clone itself, because the module always clones with ~--branch~. Declaring a just-created repository so it fills in later is unsupported until its first push — use ~cloneVerifyRemotes = "warn"~ if you need to activate before that.

*** Sequential Activation
Cloning happens during the activation phase of Home Manager. If you are cloning many large repositories for the first time, ~home-manager switch~ will wait for all clones to complete before finishing. On Linux, ~home.cloneUseSystemdService~ moves the clone execution into a background systemd user service instead.

** 🔍 Troubleshooting

#+html:<details>
#+html:<summary><strong>Repository Not Cloning</strong></summary>

1. Check if the directory already exists:
#+begin_src bash
   ls -la ~/path/to/repo
#+end_src

2. Remove and retry:
#+begin_src bash
   rm -rf ~/path/to/repo
   home-manager switch
#+end_src

#+html:</details>

#+html:<details>
#+html:<summary><strong>Preflight Blocks Activation</strong></summary>

The preflight failing means the listed repositories would not be cloneable — the report shows each repository, URL, and cause. If you want to switch anyway (e.g. the credentials arrive after this activation):

#+begin_src nix
home.cloneVerifyRemotes = "warn";  # report but continue
#+end_src

To diagnose without activating, run the doctor app:

#+begin_src bash
nix run github:rytswd/home-git-clone#check
#+end_src

#+html:</details>

#+html:<details>
#+html:<summary><strong>SSH Authentication Fails</strong></summary>

1. Verify your SSH agent:
#+begin_src bash
   ssh-add -l
#+end_src

2. Check GPG agent socket:
#+begin_src bash
   ls -la ~/.gnupg/S.gpg-agent.ssh
#+end_src

#+html:</details>

#+html:<details>
#+html:<summary><strong>HTTPS Being Rewritten to SSH</strong></summary>

This happens when you have =url.*.insteadOf= in your git config. The module should bypass this automatically for HTTPS URLs. If not:

#+begin_src nix
home.gitClone."path" = {
  url = "https://github.com/user/repo.git";
  bypassGitConfig = true;  # Force bypass
};
#+end_src
